    answer_key: >-
      The forward pass builds a directed acyclic graph where each node is a value
      and each edge records which operation produced it from which inputs. The
      backward pass walks that graph from the output toward the inputs, and at
      each node multiplies the gradient that arrived from above by the local
      derivative of the operation that produced it — which is exactly the chain
      rule, applied one edge at a time. The topological sort matters because a
      node's gradient is only complete once every path from the output to it has
      contributed. If you process a node before all of its consumers, you send
      onward a partial gradient, and everything downstream of that point is wrong
      by however much was missing. Reverse topological order guarantees that when
      you reach a node, every consumer has already been processed. This is also
      why the gradient must accumulate with += rather than assign: a node used in
      several places receives one contribution per path, and the total derivative
      is their sum.
  - prompt: "You changed `+=` to `=` in the backward pass and a gradient became wrong. Give the concrete example, and say what mathematical rule the `+=` implements."
    answer_key: >-
      The simplest case is y = x * x. There is one node x feeding two inputs of
      the same multiply, so the backward pass visits x twice: once as the left
      operand, contributing the value of the right operand, and once as the right,
      contributing the left. Each contribution is 3 when x is 3, and the correct
      total is 6. With assignment instead of accumulation, the second visit
      overwrites the first and you get 3 — exactly half. The rule += implements is
      the multivariable chain rule: when a variable influences the output through
      several paths, the total derivative is the sum of the derivatives along each
      path. This shows up constantly in real networks — any weight shared between
      time steps in a recurrent net, any parameter reused across positions, any
      skip connection where a value is both transformed and passed through
      unchanged. Every one of those is a node with more than one consumer, and
      every one of them is silently wrong if the accumulation is missing. Nothing
      raises; the loss simply stops going down as fast as it should.

## Why this node exists

Appendix B says it plainly: **explicitly not skippable.**

Every framework you will use from here hides backpropagation behind one method
call, and it is entirely possible to have a productive career never knowing what
that call does. It is also the reason a certain class of bug is impossible to
debug: gradients that are silently wrong, losses that plateau for structural
reasons, and architectures that cannot train because of where the gradient dies.

You will write about 100 lines. Karpathy's video is two and a half hours and is
the best explanation of this material that exists.

## The session

### 1. The Value class

One scalar, plus the bookkeeping to differentiate it:

```python
class Value:
    def __init__(self, data, _children=(), _op=""):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None      # how to send grad to my inputs
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad  += out.grad          # d(a+b)/da = 1
            other.grad += out.grad
        out._backward = _backward
        return out
```

Implement `__mul__`, `__pow__`, `tanh`, `exp` the same way. **Derive each local
gradient yourself before writing it.** Copying them from the reference is the one
way to spend three hours here and learn nothing.

### 2. The backward pass

```python
def backward(self):
    topo, visited = [], set()
    def build(v):
        if v in visited: return
        visited.add(v)
        for child in v._prev:
            build(child)
        topo.append(v)
    build(self)

    self.grad = 1.0                        # d(self)/d(self)
    for v in reversed(topo):
        v._backward()
```

Note `+=` in every `_backward`. That is the multivariable chain rule and it is
the single most important character in the file.

### 3. Verify against node 1.2

Import your gradcheck. Do not modify it — its independence from this code is the
whole reason it is worth anything.

Check each operation individually, then the composed expression from node 1.2:

```
z = w * x + b
s = sigmoid(z)
L = (s - y) ** 2
```

You derived those gradients by hand in node 1.2. Your engine should reproduce
them to 8 decimal places.

### 4. Break the accumulation on purpose

Change one `+=` to `=`. Test `y = x * x` at `x = 3`.

Correct: `dy/dx = 6`. Broken: `3`.

Then put it back. This is the checklist item most likely to save you a day at
some point in the future.

### 5. Train something

Build an MLP: 2 inputs, 4 hidden with tanh, 1 output. **17 parameters** —
`(2*4 + 4) + (4*1 + 1)`. Count them by hand and confirm against your code.

Train it on something a linear model cannot do — the classic two-moons or XOR.
Fit a logistic regression first for the baseline, then beat it by at least 10x
on loss.

Then gradcheck **after training**. Gradients that are correct at initialisation
and wrong at convergence is a real failure mode, usually from a saturated
activation.

## Common walls

**Your gradients are all zero.** You forgot `self.grad = 1.0` on the output
before walking backwards, or you are calling `backward()` on something that is
not the final loss.

**Gradients accumulate across training steps.** You must zero them before every
backward pass. PyTorch has the same requirement, which is why `zero_grad()`
exists and why forgetting it is a rite of passage.

**Your topological sort recurses too deep.** Python's default recursion limit is
1000. For a deep graph, write the DFS iteratively.

**tanh gradient is wrong.** `d/dx tanh(x) = 1 - tanh(x)^2`, expressible in terms
of the forward output — the same trick as the sigmoid in node 1.2, and the same
reason to cache the forward value.

**Loss decreases but gradcheck fails.** Trust gradcheck. A partially-wrong
gradient often still points roughly downhill, so the loss falling is very weak
evidence. This is exactly what node 1.2 built the checker for.

## Before you move on

Node 4.2 rebuilds the same network twice — once by hand in numpy, once in
PyTorch — and requires the two to agree. Having this engine in your head is what
makes PyTorch legible rather than magic.
